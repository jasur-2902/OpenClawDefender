# Rookbot UX Quick Reference

**Quick lookup for designers and product managers**

---

## 1. Every Page's Data Needs

### Home/Dashboard
- **What:** Protection score (0-100), score history (sparkline), recent events (5), alert count, server count
- **Loading:** Score fetch 30s TTL, events real-time, alerts fresh
- **Empty:** "All quiet so far. I am watching your AI tools."
- **Indicator:** Skeleton in score box while loading

### Activity Timeline
- **What:** All events (max 10k), grouped by time period + pattern
- **Loading:** Streaming real-time (100ms batches)
- **Empty:** "Nothing here yet. This is where you will see a live feed..."
- **Filters:** Server, status (allowed/blocked/prompted), risk (dangerous/suspicious/unusual), search, notable-only

### Alerts
- **What:** Active alerts (always fresh), severity counts, resolved/blocked stats
- **Loading:** Fresh fetch on mount + real-time
- **Empty:** "No threats detected. That is a good thing."
- **Sort:** By severity (dangerous first) → recency (newest first)

### Ask Claw (AI Chat)
- **What:** Conversation messages, past conversations, context (current page + server)
- **Loading:** Latest conversation auto-loads on startup
- **Empty:** "Hey. I'm Claw. Ask me anything..." with context-aware suggestions
- **Context:** Page location, last viewed event, custom entities sent with every question

### My Tools
- **What:** MCP server list, wrapped status, trust level, today's stats
- **Loading:** Server detect every 30s TTL
- **Empty:** "No servers connected. I protect AI tools by wrapping their MCP servers."
- **Badge:** "2 servers need wrapping" if any unwrapped

### Settings
- **What:** Theme, notifications, daemon autostart, security level, log level
- **Loading:** Persisted settings, lazy daemon info
- **Update:** Save immediately (no "Save" button), confirm toast

### System Health
- **What:** Doctor checks (pass/warn/fail), FDA status, network extension, model status
- **Loading:** On mount, poll for in-progress checks
- **Visual:** Health meter (green/yellow/red)

## 2. Real-Time Features

### Live Event Stream
- **Source:** `clawdefender://humanized-event` Tauri listener
- **Frequency:** Potentially thousands per second
- **Batching:** Grouped every 100ms before UI update
- **Prepending:** New events appear at top (LIFO)
- **Cap:** Max 10,000 events — older ones drop silently

### Live Alerts
- **Source:** `clawdefender://intelligent-alert` listener
- **Frequency:** Less often (generated by backend on pattern match)
- **Dedup:** Identical patterns within time window = 1 alert with count
- **Notification:** Routed by severity (dangerous = modal, info = timeline only)

### Pending Prompts
- **Source:** `clawdefender://prompt` listener
- **Priority:** Highest — modal overlay with countdown
- **Timeout:** 30s default (configurable)
- **Auto-block:** If no response, action blocked

### Status Changes
- **Source:** Daemon start/stop events
- **UI:** Connection state (connected/reconnecting/disconnected)
- **Icon:** Green (running) → spinner (reconnecting) → gray (disconnected)

---

## 3. Caching Strategy

### With TTL (30 seconds)
- Protection score
- Score history (sparkline)
- Server list

**Behavior:** If fresh enough, skip fetch. If stale, fetch in background. Never block UI.

### No Cache (Always Fresh)
- Alerts (re-fetched after user action)
- Conversations (loaded on demand)

### Real-Time (No Cache)
- Events (streaming continuously)
- Prompts (arrive live)

---

## 4. Connection States & Offline

### States
```
connected      → All features work, green indicator
reconnecting   → Spinner in status bar, "Trying to reconnect..."
disconnected   → Error dialog, gray UI, limited read-only mode
```

### What Still Works Offline
- View cached events
- View cached alerts
- Read conversation history
- View cached score (timestamp shows age)

### What Doesn't Work Offline
- New events won't arrive
- Can't respond to prompts
- Can't save messages (queue them)
- Can't fetch fresh data

## 9. Rate Limiting Behavior

**Rule:** If more than 10 events arrive in 5 seconds:
1. Suppress individual toast notifications
2. Show single batch toast: "A lot is happening right now — 42 events"
3. Link to Activity page

**Purpose:** Prevent notification spam during high-activity periods

---

## 10. Event Grouping Rules

Events are grouped in this order:

1. **Time Period:** right_now (5m) → earlier_today → yesterday → this_week → older
2. **Kill Chains:** Events with same `kill_chain_id` group together
3. **Prompt Sequences:** Prompt + outcome (within 60s) group together
4. **Pattern Clustering:** Same server + tool + action + path prefix within 30s window
5. **Single Events:** Ungrouped events = single-item groups

**Rendering:** Display group headers (collapsible), expand to show children

---

## 11. Event Filtering

**Available Filters:**
- **Search:** Across server, tool, action, resource, details
- **Server:** Multi-select from detected servers
- **Status:** allowed | blocked | prompted
- **Risk:** dangerous | suspicious | unusual
- **Notable Only:** Toggle to show only is_notable=true

**Implementation:** Filter in real-time as user types/selects

## 12. Pending Prompts (High Priority)

**Structure:**
```typescript
{
  id: string
  timestamp: string
  server_name: string
  tool_name: string
  action: string
  resource: string
  risk_level: "low" | "medium" | "high" | "critical"
  context: string
  timeout_seconds: number
}
```

**UI Pattern:**
- Modal overlay (not dismissible)
- Countdown timer (30s default)
- Action buttons (Allow, Block, Always Allow, Always Block)
- Risk-aware ordering: dangerous → block default, low-risk → allow default

**Behavior:**
- Timeout expires → auto-block + show toast "No response — I blocked this for now"
- User responds → prompt removed, event added to stream

## 13. Conversation Context

**Sent with every AI question:**
```json
{
  "currentPage": "/alerts",
  "lastServer": "fs-server",
  "lastEvent": "evt-12345",
  "lastEntities": { "custom_key": "value" },
  "messageCount": 15
}
```

**Usage:** AI knows what user was looking at, provides contextual answers

**Update Triggers:**
- Page navigation → update `currentPage`
- Event selection → update `lastEvent`
- Server clicked → update `lastServer`

## 16. Form Patterns

### Settings
- **Pattern:** Instant save (no Submit button)
- **Feedback:** Toast "Settings saved" (green, 3s)
- **Validation:** In-place validation (red error text)

### Conversation Input
- **Pattern:** Text input + send button (or Cmd+Enter)
- **Feedback:** Message appears optimistically, persists in background
- **Placeholder:** "Ask Claw anything..."

### Prompt Modal
- **Pattern:** No form, just display + action buttons
- **Buttons:** Primary (default action), Secondary (alt action), Dismiss (if allowed)
- **Keyboard:** Enter = primary action, B = block, A = allow, etc.

## 18. Error Messages & Recovery

### Common Errors

| Error | Message | CTA |
|-------|---------|-----|
| Daemon not running | "Claw's daemon is not running." | Start daemon |
| Lost connection | "I lost connection to the daemon. Trying to reconnect..." | Retry / Learn more |
| Server detect failed | "Could not detect servers. Check permissions." | Scan again |
| Conversation load failed | "Could not load conversation." | Try again |
| API key invalid | "Your API key is not working." | Open settings |
| Model download failed | "Could not download security model." | Retry |

**Pattern:** Error toast with action button + secondary "Learn more" link

## 21. Accessibility Notes

- **Color Blindness:** Don't rely on color alone for threat levels (use icons + labels)
- **Focus Management:** Prompts trap focus (modal), alerts allow escape
- **Keyboard Nav:** All actions accessible via keyboard
- **Screen Reader:** ARIA labels on all interactive elements
- **Motion:** Animations can be disabled (prefers-reduced-motion)

## 23. Performance Budgets

### Target Metrics
- **Score Load:** < 1s
- **Alert Fetch:** < 2s
- **Event Grouping (10k events):** < 1s
- **Page Navigation:** < 300ms
- **Prompt Display:** < 50ms (user must see immediately)

### Where to Optimize
- Virtualize event lists (don't render 10k DOM nodes)
- Debounce search input (min 300ms delay)
- Lazy load page content (System Health, etc.)
- Batch real-time updates (100ms flush)

---

## 24. Error Scenarios to Design For

1. **Daemon crashes** → Reconnecting state + "Daemon restarted" banner
2. **Event stream stops** → Stale data badge + auto-retry
3. **Network lost** → "Offline mode" indicator + queue pending actions
4. **Score is very old** → "Data from 2 hours ago" warning + refresh button
5. **Too many events** → "Older events dropped" message + archive link
6. **Prompt timeout** → "No response — blocked automatically" toast + review button
7. **Alert dedup explosion** → "Alert deduplicated 500+ times" instead of 500 alerts
8. **Malformed event** → Skip rendering, log error (user never sees)
