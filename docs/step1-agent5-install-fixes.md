# Agent 5: Install Script Fixes Summary

## Files Modified

### 1. `scripts/install.sh` — Complete Rewrite

**Before:** Downloaded pre-built binaries from GitHub Releases. Did not build from source, did not create config/data directories, did not copy default configs, did not install the LaunchAgent plist, did not set permissions.

**After:** Full local-from-source install script that:
- Builds release binaries for `clawdefender-cli` and `clawdefender-daemon` via `cargo build --release`
- Copies binaries to `/usr/local/bin/` (or `$CLAWDEFENDER_INSTALL_DIR`) with `0755` permissions
- Creates config directory `~/.config/clawdefender/` with `0755` permissions
- Creates data directory `~/.local/share/clawdefender/` with `0755` permissions
- Creates subdirectories: `models/`, `threat-intel/`, `crashes/`, `scans/`
- Writes default `config.toml` (skip if exists) with `0644` permissions
- Copies `policies/default.toml` to `policy.toml` (skip if exists) with `0644` permissions
- Generates daemon `server-token` with `0600` permissions
- Generates and installs LaunchAgent plist to `~/Library/LaunchAgents/com.clawdefender.daemon.plist` with expanded absolute paths (plists do not support `~` or `$HOME`)
- Loads the LaunchAgent via `launchctl load`
- Runs `clawdefender init` for honeypot setup and client detection

### 2. `scripts/install-release.sh` — New File

The original GitHub-release-based installer was preserved as `scripts/install-release.sh` for end-user installations that download pre-built binaries. No functional changes from the original `install.sh`.

### 3. `scripts/uninstall.sh` — Updated

**Changes:**
- Uses `launchctl list` to check if the agent is loaded before unloading (more reliable than checking file existence)
- Shows directory contents before asking to delete config/data dirs (helps user decide)
- Updated prompt text to mention models and scans in the data directory
- Consistent variable naming with install script

### 4. `com.clawdefender.daemon.plist` — Fixed

**Before:**
- `StandardOutPath` and `StandardErrorPath` pointed to `/usr/local/var/log/clawdefender/daemon.stdout.log` and `daemon.stderr.log` — a location that doesn't exist and requires root
- Two separate log files (stdout vs stderr)
- No note about `~` not working in plists

**After:**
- Both `StandardOutPath` and `StandardErrorPath` point to `/Users/YOU/.local/share/clawdefender/daemon.log` (placeholder for manual install)
- Single combined log file at the standard data directory
- Added a prominent comment explaining that macOS plists do NOT expand `~` or `$HOME`, and that users should use `scripts/install.sh` which generates the plist with correct absolute paths
- Updated manual install instructions in comments

**Note:** The repo plist is a **template**. The actual installed plist is generated by `scripts/install.sh` with the user's real `$HOME` expanded.

### 5. `justfile` — Fixed

**Changes:**
- `install` target now calls `bash scripts/install.sh` (full install with dirs, configs, plist)
- Added `install-quick` target for the old behavior (just copy binaries, no dirs/plist)
- `install-local` retains its old behavior (quick install + init) for backward compatibility
- Added `uninstall` target that calls `bash scripts/uninstall.sh`
- **Removed `build-menubar`** target that referenced the legacy Swift menu bar app at `clients/clawdefender-menubar`. This app has been superseded by the Tauri GUI app (`clients/clawdefender-app`), which is built via `build-app` and `build-dmg`.
- Added `chmod 0755` to `install-quick` and `install-local` for correct binary permissions
